## 发布门禁

1. 先完成 G0–G2 的本地单测、后端集成测试、前端类型检查和 Docker 验收。
2. G3–G6 在隔离环境验证，确认不改变现有计费、权限和用户可见行为后再进入发布候选。
3. G7–G8 与下一次官方主线升级一起验收；任何模块化重构不得绕过功能回归。
4. 生产发布顺序固定为主站 → L1 → COS。任一站健康检查、页面检查或关键接口失败，立即停止后续站点并回滚失败站点应用镜像。
5. 只保留当前镜像和上一版回滚镜像；数据库、Redis、业务卷和历史迁移不因应用回滚而恢复旧副本。

## 不在本轮范围

- 不重新引入已移除的代理商运行时功能。
- 不改变用户售价、成本倍率、余额扣减和既有 Key 路由语义。
- 不把测智结果改成账号公开信息。
- 不为了“解耦”拆成微服务、独立仓库或新增运行时网络调用。
