表中按目录的实际分配量统计，避免把 `docker system df` 的镜像和构建缓存再加到 containerd 上。镜像和构建缓存可能引用同一层，Docker 标出的可回收量也不等于根盘一定能释放的空间。主站、L1 和已停用的 COS 共用一份应用镜像；停止 COS 保留其数据和恢复能力，因此释放的主要是运行资源，磁盘下降主要来自之后的镜像和缓存清理。

备份是最大的来源，占已用空间约 39%。`/opt` 下三处发布备份共 17.86 GiB，其中按文件类型约 9.48 GiB 是 PostgreSQL 数据和导出，约 8.18 GiB 是应用数据、配置及其他归档。11 月 18 日同一天的六个部署前快照共 5.95 GiB，其中四个中间候选约 3.96 GiB，无对应成功部署记录。这些快照独立保存，每轮发版或候选重试会增加占用。

建议先梳理备份保留期和异地副本。优先复核这四个候选快照，确认没有唯一恢复点，再对需要保留的内容做异地归档、校验与恢复验证；保留最近成功发布的恢复点及 COS 的持久数据。其次可确认 VPS 是否仍需要本地 Go 构建，再决定是否清理约 4.0 GiB 的 Go 缓存。这次未删除历史备份、日志、交换文件或业务数据，也未设置自动清理。
