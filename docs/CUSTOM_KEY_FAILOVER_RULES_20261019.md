## Key 独立规则

每条规则具有共同的累计阈值和冷却时长；不同类型使用各自的统计范围。

编辑界面现将冷却放在规则列表下方，统一应用所有规则。兼容历史各条异值：不编辑冷却就保持原值，输入新冷却值后才统一；线协议与每条规则数据结构不变。新添加/变换类型沿用当前冷却，纯状态码旧默认 600 秒并不会在打开界面时被改成 120 秒。

| 类型 | 统计语义 | 编辑项与默认值 |
| --- | --- | --- |
| 首个有效内容 `ttft` | 上游首次 dispatch 后等待有效内容，安全可重放且存在备用才主动切换；慢首字次数达到阈值使后续请求冷却 | 等待 15 秒（最低 5 秒）、最近 20 次中 3 次、冷却 120 秒 |
| SLA 成功率 `sla_success_rate` | 最近 N 个有效组结果收满后，成功率严格低于百分比才冷却，不重放成功结果 | 最近 20 次低于 90%、冷却 120 秒 |
| 连续失败 `consecutive_failures` | 连续的分组最终失败结果；分组成功后重置连续次数 | 新草稿次数 5、冷却 120 秒 |
| 请求超时 `timeout` | 最近 N 次有效分组结果中，已有上游超时结果达到阈值；不是新增主动超时器 | 新草稿最近 20 次中 10 次、冷却 120 秒 |
| 分组限流 `rate_limit` | 最近 N 次有效分组结果中，上游返回 429 的次数达到阈值 | 新草稿最近 20 次中 10 次、冷却 120 秒 |
| 自定义状态码 `status_code`（高级） | 指定时间窗口内，同一上游状态码的分组最终失败次数达到阈值；不同状态码独立累计 | 次数 3、窗口 60 秒、冷却 600 秒 |

“请求超时”统计现有上游超时分类，包括 408、504、522、524；不把普通客户端取消或本地准入失败当作上游超时。“分组限流”只统计上游 429，不统计本地余额不足、用户 RPM 或 Key 限额等拒绝。

首次主动开启空草稿时，按上表预置前五条规则；已保存策略及关闭后保留的本次草稿不被默认值覆盖。仍保留高级状态码规则的添加与逐条校验。

- 按 `API Key + 分组 + 模型 + 端点` 隔离统计；高级状态码规则在此身份内再按状态码分别计数。
- 一轮分组内账号选择、重试结束后，按该分组最终结果计数一次；不能把每个账号尝试或中间错误重复累计。成功完成时记录一次成功结果，连续失败计数归零。
- 最近 N 次样本包含成功和可统计的上游失败；忽略的本地拒绝、客户端取消等不应占用样本。
- 已建立冷却后，后续失败不延长该次冷却；成功重置连续计数，但不提前取消已经建立的冷却。
- 最多 20 条规则。同一种非状态码类型不能重复；状态码规则可以多条，但状态码不能跨规则重复。状态码支持逗号分隔多个值。
- 阈值为 1–100，样本数为 1–100；次数阈值不能超过样本数，SLA 百分比不受此约束。TTFT 等待 5–3600 秒，状态码 100–599，窗口 1–3600 秒，冷却 1–7200 秒。不同类型不得携带不适用字段。
- 旧规则没有 `type` 字段时按 `status_code` 解释并保留旧载荷形状；不因打开编辑器而强行改写为新类型。

### 继承、关闭和草稿

Key 规则保存在扩展结构 `custom_api_key_route_policies`，不修改官方 API Key 表字段、Ent 模型或使用记录表。迁移 9001 为官方 Key 的软删除边界附加扩展数据清理触发器，并沿用 9000 的认证缓存失效函数；后续合并需检查这两处数据库接线。

| 配置 | 含义 |
| --- | --- |
| 省略或 `null` | 无 Key 覆盖，继承本次实际选中分组的规则，不固定继承主分组 |
| `{"rules": []}` | 显式关闭 Key 故障规则引起的冷却/切组，但保留模型不支持、真实无可调度账号时的备用路由 |
| `{"rules": [...]}` | 使用该 Key 的独立规则，不叠加分组规则 |

只有添加了备用分组，Key 编辑器才显示“故障自动切组”。移除最后一个备用分组后隐藏规则区，但不清除当前表单中的规则草稿；重新添加备用时恢复草稿。没有备用时保存使用有效值 `null`，隐藏的未完成草稿不参与校验或提交，避免无法保存。

## 一次请求的路由流程

1. 认证后取得主分组和备用顺序，保存原始请求体、原始请求模型及干净的入口上下文。
2. 依顺序检查分组状态、用户授权、模型/端点支持、组合模型映射和原生账号可调度性。已经冷却的候选优先跳过。
3. 若当前可选择的合格候选全部处于自定义路由冷却，只尝试最后一个原本合格的候选；仍重新检查原生准入、账号状态及安全限制，不循环探测所有冷却分组，也不把原生不可用账号强行恢复。
4. 进入选中平台的原生 handler，复用该分组的账号调度、重试、并发槽位、价格和计费。一个分组内的账号尝试完全结束，才记录该分组的一次最终结果。
5. 最终失败触发规则且仍有合格备用时，在尚未向客户端输出的前提下，选择下一候选。分组遍历按顺序向后，不在同一请求中绕回已尝试分组。
6. 薄 dispatcher 等待上一次原生 handler 完整返回并清理槽位等资源，恢复原始请求体和干净上下文，再进入目标平台的原生 handler；不能携带上一平台改写的 body、模型或计费上下文。
7. 已开始向客户端输出、请求取消或不能安全重放时，不再跨组重放。未触发规则、没有合格备用或备用也失败时，保留原生错误处理。

不持久化“当前备用分组”。下一次请求仍按主备优先顺序重新选择，但会尊重尚未到期的 Key/分组冷却。单分组 Key 不进入这套备用路由，不因自定义分组规则暂停账号。

## 分组规则与原生账号保护

分组管理仍维护状态码、次数、窗口和冷却时长，供没有独立 Key 规则的多分组 Key 继承。自定义分组错误规则不再写入账号的全局“停止调度”状态；这一点同时适用于单分组和多分组请求。

这不移除官方原生限流、凭证失效、账号状态或其他安全保护。自定义路由冷却不能绕过这些检查；历史手动停用、原生保护状态也不应因本轮改造批量解除。

分组规则读取使用最多 2 秒的进程内缓存。管理员保存或删除规则时，通过窄回调立即失效该分组的规则缓存、累计计数和冷却，不等待 TTL；规则语义变化后不沿用旧计数。

## 模块化接线

| 模块 | 职责 |
| --- | --- |
| `backend/internal/keyrouting` | 独立规则协议、校验、有序候选规划、窗口/样本/连续计数及冷却；不依赖 HTTP 或数据库 |
| `service/key_routing_service.go` | 适配用户授权、模型映射、原生账号 readiness、分组规则快照和 Key 规则覆盖 |
| `server/middleware/key_routing.go` | 识别可安全路由的文本 HTTP/SSE 请求，保存原始 body、模型和入口上下文 |
| `handler/key_route_dispatch.go`、`handler/key_route_failover.go` | 在原生 handler 边界收集分组最终结果、安全切换和正确平台重入；不复制原生计费器 |
| `service/group_failure_breaker.go` | 保留兼容接线及历史清理入口，不再由自定义规则全局暂停账号 |
| `service/ops_route_switch_label.go` | 为现有运维错误/恢复记录追加切组标签，不增加使用记录字段 |
| `repository/custom_api_key_routes.go`、`9001_custom_api_key_route_policies.sql` | 持久化 Key 独立规则，并对规则变更失效认证缓存 |
| `frontend/src/features/key-routing` | 主备分组编辑、规则编辑/校验与文案；由现有 Keys API 保存 |

后续官方合并优先复核这些薄接线点，以及各平台原生 handler 的成功/最终失败完成钩子，不把完整策略复制到各平台调度器。新平台也应复用相同的独立策略和原生 handler 边界。

## 安全边界与已知局限

- 仅为可安全重放的无状态文本 HTTP/SSE 请求提供备用路由。WebSocket、图片/媒体、后台任务和有状态续接不在本轮支持范围，不能把通用 Key 支持误解为所有端点都可重放。
- 已输出响应绝不重放。规则超时统计不提供主动 TTFT 截断、慢响应切换或 SLA 规则。
- 原生调度和计费保留；最终按实际使用分组计算，不新增远程价格查询或按请求写规则计数数据库。
- 计数和冷却保存在单进程内存，进程重启即清空；多副本当前不会共享这些状态。数据库保存规则配置，不保存实时窗口和冷却。若以后需要共享，应在独立 tracker 接口后增加 Redis 等实现，而不是散落修改 handler。
- Ops 标签只复用现有错误/恢复记录；不提供独立切组解释页、不改使用记录字段。
