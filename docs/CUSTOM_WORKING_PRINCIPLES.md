# 定制工作与方案评估准则

我们并不追求“绝对原创”或“从未有人做过”的完美 idea，也不要因为已有相似工作就过度防御性地否定一个方向。

已有方法在相关问题上的尝试，并不意味着这个思路失去了价值；只要能够形成清晰且有意义的差异，例如解决现有方案的不足、改善体验、满足新的需求，或者从新的视角重新组织问题、提出更有效的解决方案，这个想法就值得进一步探索。

判断的重点应是：是否存在明确的新增价值，以及进一步推进、完善或深化的空间，而不是是否完全没有先例。如果当前想法还不成熟，请具体指出可以怎样发展，不要仅以“已经有人做过”为由结束讨论。

## 在本项目中的执行方式

- 评审方案时先说明新增价值、适用边界和可验证的成功条件，再比较已有实现。
- 参考开源项目或竞品时关注机制、取舍和可复用经验，不直接把“已有先例”当作否定理由。
- 发现方案不成熟时，给出最小可行版本、风险和下一步验证，而不是只给出“不可行”的结论。
- 每个进入开发的方向都要落到代码、测试、部署或文档证据；没有证据的判断标为假设或待验证。
