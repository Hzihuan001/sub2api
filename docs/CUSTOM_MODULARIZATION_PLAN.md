## 2. 范围与不变项

### 纳入

- `operator`：角色权限、菜单和设置子页读写权限的接入边界。
- `branding`：明确展示字段及定制语言包覆盖。
- `image-studio`：前端共享策略、批量应用层拆单和异步适配的定制差异。
- `prompt-audit`：共享审计入口及定制接线。
- `usage-extras`：管理员使用记录增强的接入和权限保护。
- `gateway-resilience`：错误决策、冷却/计数执行及协议适配边界。
- 开发协作、架构检查、升级演练与验收报告。

### 必须保持

1. 外部 URL、API 字段、数据库结构、历史迁移、设置键、存储键及默认开关不变。本轮不计划数据库迁移。
2. 当前角色实际权限矩阵不变；后端仍是最终授权边界，未知权限默认拒绝。管理员使用记录可见缓存命中率、用户记录不可见的规则不变。
3. 审计各模式、捕获范围、排除规则、预览、去重、导出及清理行为不变；capture_only 不调用 Guard、不阻断正常请求。
4. 生图模型目录与白名单、原生/兼容协议、尺寸和参考图规则不变；不显示实际尺寸文字、仍可预览和下载。所有新批量无额外五折、输出优先计价、旧快照不重算。
5. 账号选择、用户/分组/账号倍率、幂等、余额预留、扣款/退款和使用记录不另写一套。
6. 已发布 `.5` 故障分类、重试预算、Retry-After、overload 窗口与恢复行为不变；已输出内容不重放，不跨分组或越权换账号。
7. 保留 HTTP/SSE/WS 各自协议边界，不强行统一转发循环；正常请求不增加远程查询。

### 不做

- 不恢复已移除的代理商运行时，不顺便新增平台、权限或重试策略。
- 不复制官方完整设置页、账号管理、计费、调度或批量系统到定制目录形成第二套实现。
- 不仅为了目录整齐移动大量文件；纯搬迁不算降低耦合的验收成果。
- 不在同一提交混合官方新版本合并、业务修复和结构重构。

## 3. 目标结构与依赖规则

结构名称为目标建议，先复用已有包；没有实际依赖收益时不强制改路径。

| 层 | 职责 | 依赖限制 |
| --- | --- | --- |
| 官方宿主 | 原路由框架、授权、调度、账务、数据库与协议处理 | 只在登记的接入点调用扩展接口 |
| 定制装配层 | 组合模块、注入适配器、注册路由和管理生命周期 | 允许接触宿主实现，是主要升级适配位置 |
| 功能模块 | 自有业务策略、UI、语言消息及测试 | 不导入 server/Wire 或其他整个 Handler；只使用声明的小接口 |
| 宿主适配器 | 将宿主账号、审计、价格和结算能力接到接口 | 复用原事务和实现，不复制核心业务 |

前端每个功能按需要声明 routes、menus、settingsPanels、read/write permissions、messages；不得把“未配置权限”解释为公开可用。后端只抽出真实需要的接口，禁止通过超大 `HostServices`、`map[string]any` 或 service locator 把全部依赖重新装进一个对象。

对官方已有功能只隔离定制差异。接口放在使用方或中立契约包，依赖单向，避免 Go 循环导入。权限与审计等必要组件缺失时必须显式报错，不能用“空插件无操作”绕过必要控制。

## 4. 分阶段执行

顺序：**P0 → P1 → P2 → P3 → P4 → P5 → P6**。每阶段单独提交、单独记录验收；失败不进入下一阶段。P2/P3 可以并行分析，不并行修改共同的宿主/注册文件。

### P0：基线统一与行为冻结

操作：

1. 从已验收 `.5` 及共享日志开始，列出其他功能会话提交、根目录未提交修改、已有 PR 和集成分支差异；不直接整分支合并旧功能分支。
2. 使用独立工作分支，例如 `codex/custom-modularization-v0.2.16`；优先复用合适且干净的工作树，否则单独建立，保留原工作树。
3. 对已有功能建立行为清单与对应测试位置，保存当前基线测试结果；已存在失败与本轮新增失败分开记录。
4. 列出目前被定制修改的主线文件、接入点、跨模块导入和历史冲突热点，记录统计口径。新增文件、测试、生成文件与业务改动分别计数。
5. 检查 `custom/integration` 与最新验收提交的祖先关系。准备安全推进方案；只有获准推送时才更新远程，不强推、不自动改变默认分支。存在分叉先给差异报告。
6. 诊断 Actions disabled 的仓库/账号层原因，记录需用户处理的项目；不擅自提高组织权限或修改计费。不能恢复时允许本地开发，但自动升级能力保持“未完成”，不得静默降级宣布通过。

交付：基线清单、功能矩阵、主线接入点清单、测试基线、阶段分支。

完成标准：候选包含 `.5` 全部已发布修复；其他会话内容有明确归属；没有未解决的关键基线失败。

### P1：先补可验证的架构边界

操作：

1. 扩展 `custom/manifest.yml` 的实际消费逻辑：登记模块所有者、宿主接入点、依赖、入口和可执行测试命令；不只添加没有工具读取的字段。
2. 扩展隔离检查：禁止不允许的反向导入、未登记的主线接入点和定制模块之间的隐式依赖。为现存例外逐项登记原因，不能用大范围白名单掩盖。
3. 加入“真实宿主接入”测试：注册一个测试模块，验证路由、菜单、设置、读写权限、语言消息及 worker 生命周期确实被宿主调用。
4. 测试重复 ID/路由/设置键失败、可选空注册集保持原行为，以及必要权限/审计组件缺失时拒绝启动或明确拒绝请求的既有策略。
5. 加入负向检查：故意在隔离夹具中漏注册入口、删权限或引入禁用依赖，门禁必须失败；不能仅依赖文件存在。

完成标准：门禁能发现“文件还在但功能断开”；现有功能保持原入口；生成代码检查与不可变迁移保护保留。

### P2：前端声明化与品牌覆盖

操作：

1. 集中定制菜单/路由及角色策略元数据，逐项替换侧栏和路由中的定制路径特判；保留官方菜单排序、模式开关和页面懒加载。
2. 为定制设置页补充独立读取、写入契约，再迁入已确认的定制面板及其读取/保存状态。官方整个 `SettingsView` 不复制、不重写。
3. 按当前权限矩阵定义全局设置权限与子页权限的关系，前后端分别验证；不能让注册元数据本身授予权限。缺读取权限不展示数据，缺写权限不发送保存请求。
4. 功能自行提供语言消息，官方语言树保持；覆盖已有键必须显式登记，意外重名使检查失败。
5. 集中品牌展示适配器：运行时站点配置优先、默认品牌兜底。只改变明确展示字段；不改 API 路径、模型 ID、环境变量、存储键、数据库名或可执行示例。
6. 生图工作台与官方批量页的重复能力/尺寸/MIME/参考图策略提取为共享纯函数或 composable，保留各供应商差异，不重新封装整套 HTTP 客户端。

验收：

- 现有最高管理员、普通管理员、operator、用户及实际权限组合的菜单/路由/设置读写矩阵不变；包含无权、只读、仅写、读写齐全和全局权限情景。
- 只读不触发写 API、直接 URL 仍受保护，后端拒绝保持。
- 标题、登录、侧栏、语言切换、运行时站点名称正确；技术链接和示例未被品牌替换误伤。
- 同一模型/协议输入的旧新图片策略输出一致；切换用户/Key、取消、迟到异步结果丢弃与 Blob URL 回收保持。

完成标准：定制设置/权限/品牌的下一次普通修改无需再改多份主线布局；前端类型、相关测试和生产构建通过。

### P3：后端统一装配与生命周期

操作：

1. 建立一个定制 composition root（装配入口），组合现有功能适配器；先迁已存在的定制接线，再移除被替代的直接注册，防止两套并存。
2. 主线保留登记的“安装、注册、启动、关闭”调用；定制模块内部不引用 server/Wire。
3. 补齐 worker Start/Stop/等待退出契约；构造与启动分开，保持依赖顺序、取消上下文、退出超时和原失败策略。
4. 保持路由路径、方法、鉴权/限流中间件及注册顺序。不要为迁移注册入口移动关键安全检查到鉴权前后不同位置。
5. Wire/Ent 由锁定工具链在独立生成环境生成、比对，不手工维护生成产物；本阶段不改 Ent schema。

验收：启动/关闭重复调用安全、worker 恰好启动一次；启动失败不会遗留工作线程；关闭可等待退出，未完成任务能由现有持久化状态恢复；路由清单与中间件链一致。

完成标准：新增一个已定义类型的定制模块不再需要修改多份主线启动/清理文件；真实应用启动而非仅空 Host 单测通过。

### P4：生图与审计的窄接口

操作：

1. 用窄 `AuditGate`（名称待实施确定）替代 `BatchImageHandler → 整个 OpenAIGatewayHandler` 依赖；复用现有审计协调器，不建立第二套审计实现。
2. 保持审计相对鉴权、请求改写、费用预留及上游提交的顺序。HTTP 去重、WS 的轮次/阶段语义和错误格式不变。
3. 生图模块按实际需要使用账号选择、定价快照、结果仓储及结算接口；保留原事务边界、锁、CAS 和核心账务代码，禁止拆成多个失去原子性的调用。
4. 先抽规则/适配边界，再决定是否移动文件；不把官方 Provider/队列/服务整套复制到定制模块。

验收：

- 审计 off/capture_only/异步/blocking 的既有语义，blocking 失败策略及 capture_only 写入失败不影响正常请求均保持。
- 同一请求不重复审计，WS 不把上一轮结果复用于下一轮；批量入口不绕过审计。
- 重复幂等键、取消、部分成功、断网、重启、重复队列投递及迟到回调不重复提交/扣款/退款；未知提交结果继续按已有保护处理。
- 旧任务能恢复，价格快照和历史账目不改；参考图、单张/ZIP 下载、使用记录与余额变动一致。

完成标准：批量 Handler 不再依赖整个网关 Handler；同一组合夹具重构前后任务结果和账目一致。

### P5：故障策略与执行分离（最后改核心网关）

操作：

1. 保留 `.5` 规则，把决策抽为不访问数据库、缓存或网络的纯逻辑，输入已归一化错误和当前尝试状态，输出明确 Decision。
2. 冷却、计数、健康状态等副作用由尝试级执行边界处理；凭据刷新、模型级/账号级隔离沿用原语义，不扩大为全账号停用。
3. HTTP/SSE/WS 保留各自解析、实际内容写出/提交边界及响应格式，只通过适配器调用决策和执行器。
4. 副作用幂等以真实 attempt 身份/生命周期约束，不能把单次上游配对错误算两次，也不能吞掉下一次真实失败。

验收：保留现有 Docker 11 场景及相关 HTTP/SSE/WS 单测；覆盖滚动窗口、Redis 降级、管理员恢复、Retry-After、凭据刷新、并发迟到错误、有效输出后失败和客户端取消。冷却阈值、次数、等待时间、后续账号选择和扣费结果与 `.5` 一致。

完成标准：新增或调整纯错误策略主要触及策略模块及测试，不需重复改三种协议处理；不增加正常请求的网络/数据库操作。

### P6：联合验收、升级演练与交付

操作：

1. 运行最终候选完整门禁与隔离 Docker 联合验收；官方兼容接入、角色/设置、审计、生图、计费、故障切换、重启恢复一起验证。
2. 对历史冲突热点做边界演练：路由/菜单重排、官方设置新增、账号/模型能力变化、Wire 重新生成。验证定制仍通过适配器接入，丢失接线会被门禁发现。
3. 若做真实历史合并对比，必须使用相同官方起点、目标和相同功能集合。只有可低成本构造等价夹具时才比较；不能在已经包含 v0.2.16 的分支再次合并 v0.2.16 并声称“零冲突”。不为演练回移整套新业务到旧版本。
4. 本轮不自动追最新官方版本。下一次真实版本升级另行指定目标，并记录实际冲突和耗时作为最终效果验证。

## 6. 验收指标

不是以“新建多少目录/接口”或“移动多少行”为完成标准，也不预先承诺降低某个百分比。

- 所有已列入清单的实际功能都能通过真实宿主集成测试，漏接入口必定失败。
- 目标边界完成依赖倒置：消除批量 Handler 对完整网关 Handler 的依赖、重复定制注册和新增的未登记主线补丁点。
- 对每阶段给出主线接入文件、接入位置、跨模块依赖和重复规则的前后清单；若拆分没有降低耦合，暂停继续扩展接口。
- 关键权限、账务、审计、协议输出和异步恢复契约全部通过；没有未解决的新增回归。
- 对相同测试负载比较请求延迟和资源占用；正常请求新增远程调用数为 0。性能阈值在 P0 根据可重复测量制定，不用一次噪声测量作结论。
- Actions 实际能运行、升级基线包含最新验收功能、草稿 PR 和报告可生成，才标记“自动升级链路完成”。否则文档明确保留阻塞项，不妨碍已验证的代码阶段单独交付。

## 7. 停止条件与回退

任一情形停止当前阶段，保留日志与失败复现，不继续发布：

- 路由缺失/重复、权限链变化、只读变可写或审计被绕过。
- worker 重复启动、无法退出、重启后任务丢失或重复提交。
- 余额/费用/快照/使用记录不一致，重复扣款/退款或冻结余额无法释放。
- 安全拒绝触发换号、模型错误扩大为不当停用、重复计数、重试预算增加或输出后重放。
- 必须修改历史迁移、数据库结构、公开 API 或恢复生产数据库才能完成纯重构。
- 核心调用路径明显变慢、出现新的请求期远程查询，或改造超出已批准范围。

代码回退按独立阶段提交处理，不重置他人工作树。已经发布时优先回退应用镜像；本方案要求数据和 API 兼容，因此不应需要恢复旧库覆盖新业务。若发现不可兼容数据变更，先停下重新审批。
