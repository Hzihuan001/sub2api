# 代理商可靠性与批量操作（2026-09-07）

## 本轮变更

- 主站目录 ETag 改为完整目录内容的 SHA-256，不再依赖各产品版本最大值。新增、撤销、低版本产品更新、模型及凭证状态变化均可使缓存失效。保留原 `catalog_version` 字段兼容性；生成时间不参与 ETag。
- 主站支持按平台排列、多选分组批量授权，自动使用 `group-ID` 产品代码。跳过已有分组，对已被其他分组占用的自动代码报错，避免覆盖。
- L1 已连接时可以重新兑换同一主站、同一代理商的新授权码。
- L1 重新授权和轮换 Key：产品加密凭证、已创建账号的实际 Key、调度缓存 outbox 在同一个本地数据库事务中写入。保留账号其他字段、分组、售价及历史数据。
- L1 的重新授权、目录同步、产品配置和 Key 轮换在进程内串行执行；重新授权与刷新令牌也互斥。
- 撤销授权后的本地停用失败会在后续目录同步中重试，包括 HTTP 304。
- L1 支持按各产品填写的销售名称/倍率批量启用或保存；加载时读取已有本地销售名称，不用上游名称覆盖。
- L1 销售倍率不再校验成本下限，不需要 allow_loss 开关；允许有效非负数（含 0 和低于成本的倍率）。新产品默认倍率为 1，不再按成本加 0.05。零倍率仅由代理产品内部调用显式启用，普通分组管理入口原有规则不变；主站成本和实际结算不受此变更影响。
- 批量写入逐项执行、去重、显示成功/失败，成功项取消勾选，仅保留失败项供重试。这不是全批次原子事务。

## 第二轮三项修复

- 对账 SQL 改为先在 CTE 中关联迟到的使用记录，再更新对应利润行，避免 UPDATE 目标表在 LATERAL 中的非法引用。每次最多补齐 1000 条，已补齐记录不重复改写；零售价及亏损正常记录。对账失败返回错误并记录连接错误状态，后续同步继续重试。
- 主站读取授权目录时从原分组刷新基础倍率和模型快照，仅变化时递增产品版本；并发改价时校验源值，防止旧快照覆盖新配置。停用、删除或改为订阅的源分组不再出现在有效目录中。L1 仍按每 5 分钟/手动同步获取更新，更新已有本地分组的模型展示和上游账号成本，不改本地销售名称、售价、启用状态或 Key。即使远端返回 304，本地未完成的应用步骤也重试。
- 分组/账号创建通过内部 context 标记进入事务化仓储路径，锁定产品行，把资源创建、产品恢复指针、调度 outbox 一起提交。后续绑定失败、响应丢失或再次创建会复用已有资源；没有新增数据库迁移，也不会自动删除旧版产生的历史孤立资源。页面显示可复用资源并在失败后保留输入售价。

验证补充：真实 PostgreSQL 16 完整迁移环境通过目录改价/模型刷新、不变版本不递增、源分组停用，以及创建失败回滚、绑定失败重试、重复请求复用测试。独立 PostgreSQL 合成数据验证迟到日志、raw/client/local 请求 ID、零售价、负利润和重复对账。仓储普通测试初次被本机代理影响；在测试进程内清除代理变量后全部通过，未修改生产网络设置。

## 换绑操作

1. 主站选择新的普通计费用户。旧 Key 立即停用；余额与历史记录不迁移。
2. 为所有仍需使用的产品生成新授权码。
3. L1「重新授权 / 计费账号换绑后同步 Key」兑换授权码；已启用账号的 Key 自动同步，不再需要维护脚本。
4. 检查目录同步状态和产品调用。缓存传播使用现有 outbox，可能有短暂延迟。

主站和 L1 之间不是分布式原子事务。如果主站已兑换成功，但 L1 本地事务失败，一次性授权码已经消耗，需要重新签发再兑换；本地不会出现凭证只更新一半的状态。本轮没有实现主站换绑后无人工步骤的两阶段切换。

## 验证

- 两端受影响后端包及路由测试。
- 目录内容变化/顺序与时间稳定性测试。
- 重新授权提交/回滚、304 下失败重试测试。
- 独立 PostgreSQL 16 容器验证凭证/outbox 原子性、回滚、无销售配置变更。
- 两端批量工具测试；L1 已连接重新授权入口、销售名称/倍率保留、非超级管理员不可见的组件测试。
- 两端前端类型检查、受影响文件 ESLint、Vite 生产构建、diff 空白检查。

测试使用合成数据，没有新数据库迁移。计划发布主站 `0.2.1-custom.5` 与 L1 `0.2.1-l1.5`，部署前备份两端数据库、配置、数据目录和旧镜像信息；只重建应用容器。部署结果以运行报告为准。
